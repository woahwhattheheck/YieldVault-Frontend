# Content Security Policy & dependency gates

This document explains the production CSP shipped by YieldVault Frontend, the
justified exceptions, and the CI dependency failure policy.

## Source of truth

All header values come from [`security/policy.mjs`](../security/policy.mjs).
Hosting configs are generated by:

```bash
npm run security:emit-headers
```

That writes:

- `public/_headers` — Netlify / Cloudflare Pages
- `vercel.json` — Vercel

`vite preview` applies the same headers via the plugin in `vite.config.js`, so
local production smoke tests match deployed behavior.

## CSP summary

| Directive | Value | Notes |
| --- | --- | --- |
| `default-src` | `'self'` | Deny-by-default |
| `script-src` | `'self'` | **No** `'unsafe-inline'` / `'unsafe-eval'` |
| `style-src` | `'self' 'unsafe-inline'` | Exception — see below |
| `img-src` | `'self' data: blob:` | Exception — chart export |
| `connect-src` | `'self'` + Stellar Horizon/Soroban origins | Wallet/network |
| `worker-src` | `'self' blob:` | Exception — blob workers |
| `object-src` | `'none'` | |
| `frame-ancestors` | `'none'` | Clickjacking defense |
| `base-uri` / `form-action` | `'self'` | |
| `upgrade-insecure-requests` | (flag) | |

Related headers: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`,
`Permissions-Policy`, `Strict-Transport-Security`, `Cross-Origin-Opener-Policy`.

## Justified exceptions

### `style-src 'unsafe-inline'`

Several React components (for example `ChartContainer`) set dynamic inline
styles. Moving those to CSS variables / classes is tracked as follow-up work;
until then `'unsafe-inline'` is required for styles only. Script execution
remains blocked from inline styles by keeping `script-src` strict.

### `img-src data: blob:`

`html2canvas` chart downloads create `blob:` object URLs. Some icons may use
`data:` URIs. Remote image hosts are **not** allowlisted.

### `connect-src` Stellar origins

Freighter (and compatible wallets) bridge into the page through an extension
content script, so `chrome-extension:` does not need to appear in page CSP.
Once mock services are replaced, the page must call Horizon and Soroban RPC.
Allowed origins are pinned to the catalog in `src/lib/networks.js` plus
Futurenet for contributor testing — see `WALLET_CONNECT_ORIGINS` in the policy
module.

### `worker-src blob:`

Production Vite chunks (and some Stellar SDK helpers) may use `blob:` workers.
Remote `worker-src` hosts are denied.

## Dependency CI policy

`npm run audit:deps` enforces:

1. **Fail** the build on **critical** `npm audit` findings.
2. **Warn** on high / moderate / low findings (visible in CI logs).
3. **Fail** on packages whose license matches a disallowed pattern (AGPL, GPL,
   SSPL, BUSL, Commons Clause, proprietary) or is otherwise outside the
   allowlist in `DEPENDENCY_POLICY`.
4. **Warn** on `UNKNOWN` licenses (often stub `package.json` files).

Compound license expressions preserve [SPDX grouping and operator precedence](https://spdx.github.io/spdx-spec/v2.3/SPDX-license-expressions/#d45-order-of-precedence-and-parentheses):
every `AND` requirement must be allowed, while `OR` offers a choice between
complete alternatives. For example, `MIT AND LicenseRef-NotApproved` fails,
but `(MIT AND GPL-3.0) OR Apache-2.0` can use the approved Apache alternative.
`WITH` exceptions must be allowlisted together with their license. Malformed
expressions fail even if they contain an allowed license; a standalone
`UNKNOWN` retains the warning-only treatment above.

Actionable remediation is printed on failure (upgrade/replace package, refresh
lockfile, or document an allowlist change).

## Rollout notes

1. Merge emits hosting header files — confirm your host honors `_headers` or
   `vercel.json`.
2. After deploy, curl the production origin and confirm `Content-Security-Policy`
   matches `security/policy.mjs`.
3. If a new wallet provider requires an origin, add it to `WALLET_CONNECT_ORIGINS`
   with a justification in `CSP_EXCEPTIONS`, regenerate headers, and extend tests.
4. Dev server (`npm run dev`) intentionally does **not** apply the production CSP
   so Vite HMR keeps working. Use `npm run preview` / `npm run smoke:headers` for
   production-parity checks.
